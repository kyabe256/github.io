・関数＝ひとまとまりの処理に名前をつけたもの。引数（渡す値）を受けとり、結果を戻り値として返す
・線形探索は先頭から順に調べる（最大 $n$ 回）。二分探索は整列済みのデータで中央と比べて範囲を半分にしていく（最大でおよそ $\log_2 n$ 回）
・選択ソートは「残りの最小値を先頭へ」、バブルソートは「隣どうしを比べて逆順なら交換」。どちらも比較回数は $n(n-1)\div2$
・計算量：データ量 $n$ が増えたときの手間の増え方。$n$ が2倍になると、線形探索は2倍、バブルソートは約4倍、二分探索は1回増えるだけ

講義1　関数 ― 引数と戻り値

要素数(Data) は配列 Data を引数として受けとり、要素の個数を戻り値として返す関数である。共通テストでは、使う関数の働きはその都度問題文で説明される。本書でも、要素数(配列)、整数(x)（x の小数点以下を切り捨てた値を返す）、乱数()（0 以上 1 未満の数をランダムに返す。第8章）などを、説明を添えて使う。
関数は自分で作ることもできる。たとえば「個数 kosu と単価 tanka を受けとり、10 個以上なら1割引きした金額を、そうでなければ kosu × tanka を返す関数 kingaku(kosu, tanka)」は、Python では次のように書く。 
def kingaku(kosu, tanka):
    if kosu >= 10:
        return kosu * tanka * 9 // 10   # 9割（整数）
    else:
        return kosu * tanka

講義5　分割統治 ― マージソート

選択ソートやバブルソートの手間は $n^2$ に比例する。より速い整列法の代表が、問題を小さく分けて解き、結果を組み合わせる分割統治の考え方を使うマージソートである。

①データを半分ずつに分け、1個ずつになるまで分割する。②整列済みの2つの列を、それぞれの先頭どうしを比べて小さいほうを取り出すことをくり返して1つの整列済みの列にまとめる（マージ）。
例：[38, 27, 43, 3, 9, 82, 10, 15] → [27, 38] [3, 43] [9, 82] [10, 15] → [3, 27, 38, 43] [9, 10, 15, 82] → [3, 9, 10, 15, 27, 38, 43, 82]
最後のマージは、先頭どうしの比較（3と9、27と9、27と10、27と15、27と82、38と82、43と82）の7回で済み、残った 82 を後ろにつける。
分割の段数は約 $\log_2 n$ 段、各段のマージの手間は $n$ に比例するので、全体の手間は約 $n\log_2 n$ に比例する。$n=10^6$ では、$\frac{n(n-1)}{2}\fallingdotseq5\times10^{11}$ 回に対し $n\log_2 n\fallingdotseq2\times10^{7}$ 回で、2万倍以上の差になる。
・整列していないデータに二分探索を使う。
・中央の添字を (hidari + migi) / 2 として小数にしてしまう（÷ で整数にする）。範囲の更新を hidari = aida とすると、終わらなくなることがある。
・バブルソートの比較回数を $n^2$ や $n(n-1)$ とする。1回目のパスは $n-1$ 回、2回目は $n-2$ 回…なので合計 $\frac{n(n-1)}{2}$ 回。

講義1　モデル化とモデルの分類

表現の形式による分類：
・物理モデル：実物や模型で表す。実物大の実物モデル（自動車の衝突実験用の人形）、大きさを変えた縮尺モデル（地球儀、風洞実験の模型）。
・図的モデル：図で表す。路線図、フローチャート、回路図、状態の移り変わりを表す状態遷移図など。
・数式モデル：数式で表す。落下距離 $y=\frac12gt^2$、預金の残高、人口の増減など。
時間による分類：時間で変化しない静的モデル（建物の間取り図）と、時間とともに変化する動的モデル（人口の推移）。
不確定な要素による分類：条件が決まれば結果が1通りに決まる確定的モデル（預金の利息）と、偶然に左右される要素を含む確率的モデル（サイコロ、客の来店）。
モデル化は、①目的を明確にする → ②目的に関係する要素を取り出し、関係の薄いものは省く → ③要素どうしの関係を式や図で表す → ④シミュレーションする → ⑤結果を現実と比べて検証し、必要ならモデルを修正する、という手順で行う。
次の①〜④は、表現の形式ではどのモデルにあたるか。また、③・④は確定的・確率的のどちらか。
① 自動車の空気抵抗を調べるための縮小模型　② 鉄道の路線図　③ 年利 1 % の複利で預けた預金の10年後の残高の計算　④ 客がいつ来るかわからないスーパーのレジの待ち時間の予測
解　① 物理モデル（縮尺モデル）　② 図的モデル（駅の順序とつながりだけを残している）　③ 数式モデル・確定的（利率と期間が決まれば残高は1通り）　④ 確率的（客の到着に偶然の要素がある。数式モデルや、乱数を使うシミュレーションで扱う）

講義1　LAN とインターネット、パケット通信

家庭・学校・会社の中のネットワークを LAN、離れた地点の LAN どうしを結ぶ広域のネットワークを WAN という。LAN の中では、スイッチ（ハブ）や無線 LAN アクセスポイント（AP）が機器をつなぎ、ルータが異なるネットワークの間でデータを中継して、宛先までの経路を選ぶ。インターネットへの接続は ISP（インターネットサービスプロバイダ）が提供する。 電話のように通信の間じゅう回線を占有する方式を回線交換方式という。インターネットでは、データを小さなパケットに分け、それぞれに宛先・送信元・順番などを書いたヘッダをつけて送るパケット交換方式を使う。1本の回線を多くの通信で共有でき、途中の経路に障害があってもルータが別の経路で送ることができ、誤りがあればそのパケットだけを再送すればよい。受信側はヘッダの情報をもとにパケットを並べ直して元のデータに戻す。

(2) 例：1本の回線を複数の通信で共有でき、回線を効率よく使える／障害が起きても別の経路でパケットを届けられる／誤りが生じたパケットだけを再送すればよい。

講義3　IP アドレスとサブネット、ドメイン名と DNS

IPv4 の IP アドレスは 32 ビットで、8 ビットずつ区切った4つの10進数で「192.168.10.37」のように書く。表せる数は $2^{32}=4{,}294{,}967{,}296$（約43億）で不足するため、128 ビット（$2^{128}\fallingdotseq3.4\times10^{38}$ 通り）の IPv6 への移行が進んでいる。
IP アドレスは、どのネットワークかを表すネットワーク部と、その中の機器を表すホスト部からなる。「192.168.10.37/26」の /26 は、先頭 26 ビットがネットワーク部であることを表し、これを1が26個並ぶサブネットマスク 255.255.255.192 でも表す。IP アドレスとサブネットマスクのビットごとの AND をとると、ネットワークのアドレス（ホスト部がすべて 0）が得られる。ホスト部がすべて 0 のアドレスとすべて 1 のアドレス（ブロードキャストアドレス）は機器に割り当てないので、/$n$ のネットワークで使える台数は $2^{32-n}-2$ である。
人が覚えやすい ドメイン名（www.example.co.jp）は、右から jp（国）、co（組織の種類＝企業）、example（組織名）と階層になっており、左端の www はサーバの名前（ホスト名）である。ドメイン名から IP アドレスを調べることを名前解決といい、DNS サーバが担う。
IP アドレス 192.168.10.37/26 のパソコンについて答えよ。(1) サブネットマスクを10進数で表せ。(2) このパソコンが属するネットワークのアドレスとブロードキャストアドレスを求めよ。(3) このネットワークで機器に割り当てられる IP アドレスはいくつか。(4) 192.168.10.70 の機器は同じネットワークにあるか。
解　(1) 先頭 26 ビットが 1 なので、第4オクテットは $11000000_{(2)}=192$。255.255.255.192
(2) 第4オクテットの $37=00100101_{(2)}$ と $11000000$ の AND は $00000000$。ネットワークアドレスは 192.168.10.0、ホスト部をすべて 1 にした 192.168.10.63 がブロードキャストアドレス。
(3) ホスト部は $32-26=6$ ビットなので $2^6-2=$ 62 個（192.168.10.1〜192.168.10.62）。
(4) $70=01000110_{(2)}$ と $11000000$ の AND は $01000000=64$ で、ネットワークアドレスが 192.168.10.64 になるので同じネットワークではない（通信にはルータを経由する）。

講義4　Web と電子メールのしくみ、通信速度

Web：URL「https://www.example.jp/info/index.html」は、通信の方式（https）、サーバのドメイン名（www.example.jp）、サーバ内のファイルの場所（/info/index.html）を表す。ブラウザは DNS で IP アドレスを調べ、Web サーバに HTTP でリクエストを送り、サーバは HTML などをレスポンスとして返す（見つからなければエラー「404 Not Found」）。HTTPS は通信を暗号化し、電子証明書でサーバが本物であることを確かめる（第10章）。
電子メール：送信者のメールソフト → SMTP → 送信側のメールサーバ → SMTP → 受信側のメールサーバ（メールボックス）→ 受信者が POP または IMAP で受けとる。POP はメールを端末に取りこんで読む方式、IMAP はメールをサーバに置いたまま読む方式で、複数の端末から同じ状態で読める。宛先の BCC に入れたアドレスは、ほかの受信者に表示されない。
通信速度は1秒間に送れるビット数で、単位は bps（ビット毎秒）。通信速度の k・M・G はふつう $10^3$・$10^6$・$10^9$ 倍を表す。実際には制御のための情報や混雑があるので、理論上の速度に対する実際の割合（伝送効率）を掛けて考える。
(1) 600 MB のファイルを、通信速度 100 Mbps、伝送効率 80 % の回線でダウンロードするのに何秒かかるか（1 MB＝$10^6$ バイト）。
(2) 50 MB の動画を 10 秒で送るには、少なくとも何 Mbps の通信速度が必要か（伝送効率 100 %、1 MB＝$10^6$ バイト）。
解　(1) データ量は $600\times10^6\times8=4.8\times10^9$ ビット。実際の速度は $100\times10^6\times0.8=8\times10^7$ bps。$4.8\times10^9\div(8\times10^7)=$ 60 秒。
(2) $50\times10^6\times8=4\times10^8$ ビットを 10 秒で送るので、$4\times10^7$ bps＝40 Mbps。
(1) ルータの役割を簡潔に述べよ。
(2) IPv4 の IP アドレスは何ビットか。また IPv6 は何ビットか。
(3) /24 のネットワークで、機器に割り当てられる IP アドレスはいくつか。
(4) 1枚 3 MB の写真 20 枚を、20 Mbps の回線で送るのに何秒かかるか（伝送効率 100 %、1 MB＝$10^6$ バイト）。
・通信時間の計算は「バイト → ビット（×8）」「伝送効率」「1 MB を $10^6$ とするか $2^{20}$ とするか」の指示を確認する。
・IP アドレスは、ネットワーク部の長さから割り当て可能な台数（ホスト部が $h$ ビットなら $2^h-2$）や、同じネットワークかどうかの判定（AND をとって比べる）が問われる。
・TCP/IP の層とプロトコルの対応、TCP と UDP の使い分け、POP と IMAP の違い、DNS の役割は知識問題の定番。

講義5　プライベート IP アドレスとアドレス変換（NAT）

IPv4 のアドレスは足りないので、LAN の中では、インターネット上では使われないプライベート IP アドレスを使うことが多い。インターネット上で一意に割り当てられるアドレスはグローバル IP アドレスという。

プライベート IP アドレスの範囲は、10.0.0.0〜10.255.255.255、172.16.0.0〜172.31.255.255、192.168.0.0〜192.168.255.255 と決められている。異なる LAN で同じプライベートアドレスを使ってもかまわない。
LAN の機器がインターネット上のサーバと通信するときは、境界のルータが、パケットの送信元をプライベートアドレスから自分のグローバルアドレスに書きかえて送り、返ってきたパケットの宛先を元に戻す（NAT、アドレス変換）。さらにポート番号も組み合わせて変換すれば（NAPT）、1つのグローバルアドレスを LAN 内の多数の機器で共有できる。家庭のルータはふつうこの働きをもつ。
外部から LAN 内の機器に直接パケットを送りにくくなるので、結果として防御にも役立つ。ただし、それだけで安全になるわけではなく、ファイアウォールなどの対策と組み合わせる（第10章）。
・バイトとビットの換算忘れ（通信速度はビット毎秒）。
・/$n$ の割り当て台数で「$-2$」を忘れる（ネットワークアドレスとブロードキャストアドレスは使えない）。
・DNS を「Web ページを保存するサーバ」と誤解する。DNS はドメイン名と IP アドレスの対応を答えるしくみ。
・TCP を「速い」、UDP を「確実」と逆に覚える。

講義2　認証とパスワードの強さ

利用者が本人であることを確かめることを認証という。認証に使う情報は次の3種類に分けられる。
・知識情報：本人だけが知っていること（パスワード、暗証番号）
・所有情報：本人だけが持っているもの（スマートフォン、IC カード、ワンタイムパスワードを表示する機器）
・生体情報：本人の身体の特徴（指紋、顔、静脈、虹彩）
異なる種類を2つ以上組み合わせる多要素認証（例：パスワード＋スマートフォンに届く確認コード）は、パスワードが漏れても不正ログインを防げる。パスワードと「秘密の質問」の組合せは、どちらも知識情報なので多要素認証ではない。
パスワードを1文字ずつ全通り試す総当たり攻撃に対しては、使える文字が $k$ 種類で長さが $L$ 文字なら $k^L$ 通りあるので、種類を増やし、長くするほど強くなる。ただし、辞書の単語や誕生日などは辞書攻撃で推測されやすい。また、別のサービスから漏れた ID とパスワードの組を試す攻撃があるので、使い回しをしない。

① 数字4けた　② 英大文字・小文字・数字（62種類）の8文字　③ ②と同じ文字の12文字

② $62^8\fallingdotseq2.2\times10^{14}$ 通り。$2.2\times10^{4}$ 秒 ＝ 約 6.1 時間。
③ $62^{12}\fallingdotseq3.2\times10^{21}$ 通り。$3.2\times10^{11}$ 秒 ＝ 約 1.0 万年（$3.2\times10^{11}\div(3600\times24\times365)\fallingdotseq1.0\times10^4$）。
長さを 8 文字から 12 文字にするだけで、$62^4\fallingdotseq1.5\times10^7$ 倍になる。

講義3　暗号とデジタル署名

元の文を平文、読めないように変換した文を暗号文、変換を暗号化、元に戻すことを復号といい、変換の手順に使う値を鍵という。アルファベットを一定の数だけずらすシーザー暗号（3文字ずらすと INFO → LQIR）は、鍵が25通りしかないので総当たりですぐ破られる。現代の暗号は、鍵の候補が天文学的な数になるように作られている。
・共通鍵暗号方式：暗号化と復号に同じ鍵を使う。処理は速いが、鍵を相手に安全に渡す方法が問題になり、$n$ 人が互いに通信するには $\frac{n(n-1)}{2}$ 個の鍵が必要。
・公開鍵暗号方式：対になる公開鍵（誰に知られてもよい）と秘密鍵（本人だけが持つ）を使う。送信者は受信者の公開鍵で暗号化し、それを復号できるのは受信者の秘密鍵だけ。鍵を渡す問題は解決するが、処理は遅い。$n$ 人で $2n$ 個の鍵で済む。
Web の HTTPS（SSL/TLS）では、公開鍵暗号で共通鍵を安全に送り、データ本体は速い共通鍵暗号で暗号化する（ハイブリッド方式）。
デジタル署名：送信者は文書からハッシュ値（文書が1文字でも変わると全く違う値になる、短い要約値）を求め、それを自分の秘密鍵で暗号化して署名とし、文書に添えて送る。受信者は送信者の公開鍵で署名を復号し、受けとった文書から求めたハッシュ値と比べる。一致すれば、①送信者本人が作ったこと（なりすましでない）、②途中で改ざんされていないこと、が確かめられる。公開鍵が本当にその人のものであることは、認証局が発行する電子証明書で保証する。
(1) 3文字後ろにずらすシーザー暗号でつくった暗号文「PDWK」を復号せよ。
(2) 50 人が互いに秘密の通信をするとき、共通鍵暗号方式と公開鍵暗号方式では、それぞれ全部で何個の鍵が必要か。
(3) A さんが B さんに、公開鍵暗号方式で秘密の文書を送る。暗号化と復号にはそれぞれ誰のどの鍵を使うか。
(4) A さんが文書にデジタル署名をつけて B さんに送る。署名の作成と検証にはそれぞれ誰のどの鍵を使うか。
解　(1) 各文字を3文字前に戻して P→M、D→A、W→T、K→H で「MATH」。
(2) 共通鍵：$\frac{50\times49}{2}=$ 1225 個。公開鍵：1人2個（公開鍵と秘密鍵）で 100 個。
(3) 暗号化は B さんの公開鍵、復号は B さんの秘密鍵。
(4) 作成は A さんの秘密鍵、検証は A さんの公開鍵（A さんの秘密鍵を持つのは A さんだけなので、A さん本人の署名だとわかる）。

講義4　誤り検出 ― パリティビット

通信や記録の途中で、雑音などにより 0 と 1 が入れかわる誤りが起こることがある。パリティビットは、データに1ビットを追加して、全体の1の個数を偶数（偶数パリティ）または奇数（奇数パリティ）にそろえる方法である。たとえば 7 ビットのデータ 1011001 は1が4個なので、偶数パリティでは 0 を追加して 10110010 とする。受信側で1の個数を数え、奇数なら誤りがあるとわかる。
ただし、2ビットが同時に反転すると偶奇が変わらないので検出できない（検出できるのは奇数個の誤り）。また、どのビットが誤っているかはわからない。
そこで、データを縦横に並べて行ごと・列ごとにパリティをつける水平垂直パリティを使うと、1ビットの誤りなら、偶奇が合わない行と列の交わる位置として場所を特定して訂正できる。書籍の ISBN や商品のバーコードの末尾の数字（チェックディジット）も、読み取りの誤りを検出するためのものである。
(1) 7 ビットのデータ 1101100 と 0110100 に、偶数パリティのビットを末尾に追加せよ。
(2) 偶数パリティを末尾につけた 8 ビットのデータ 11010110 を受信した。誤りはあるか。
(3) 4ビット×4行のデータの各行の右端と最下行に偶数パリティをつけて送ったところ、右の表のように受信した。誤っているビットの位置を答え、訂正せよ。

3行11000
4行01010

解　(1) 1101100 は1が4個 → 11011000。0110100 は1が3個 → 01101001。
(2) 1が5個（奇数）なので、誤りがある（どこかは特定できない）。
(3) 各行の1の個数は 4, 1, 2, 2, 2 で、2行目だけが奇数。各列は 2, 4, 1, 2, 2 で、3列目だけが奇数。よって2行3列のビットが誤り。0 を 1 に訂正すると、2行目は 0110（パリティ 0）となり、すべての行・列が偶数になる。
(1) 定期的にデータのバックアップをとることは、3要素のうち主にどれを高める対策か。
(2)「パスワード」と「秘密の質問の答え」を組み合わせた認証は多要素認証といえるか。理由も答えよ。
(3) 10 人が互いに共通鍵暗号方式で通信するには、鍵は何個必要か。
(4) 7 ビットのデータ 1011010 に、奇数パリティのビットを末尾に追加せよ。
・3要素は「何が損なわれたか」「どの対策がどれを高めるか」を事例で判断させる。
・公開鍵暗号とデジタル署名は「誰の・どちらの鍵か」がすべて。暗号化は受信者の公開鍵、署名は送信者の秘密鍵。
・鍵の個数（$\frac{n(n-1)}{2}$ と $2n$）、パスワードの組合せ数（$k^L$）、パリティの計算と誤りの位置の特定は計算問題の定番。

講義5　公開鍵暗号のしくみ ― 小さな数で RSA 暗号を体験する

代表的な公開鍵暗号の RSA 暗号は、「大きな2つの素数の積は簡単に計算できるが、積から元の素数を求める（素因数分解する）のは非常に難しい」ことを安全性の根拠にしている。ここでは小さな数で計算を体験する。

①素数 $p=5,\ q=11$ を選び、$n=pq=55$、$(p-1)(q-1)=40$ とする。②40 と互いに素な $e=3$ を選ぶ。③$e\times d$ を 40 で割った余りが 1 になる $d$ を求めると $d=27$（$3\times27=81=2\times40+1$）。
公開鍵は $(n,e)=(55,\ 3)$、秘密鍵は $d=27$（$p,q$ も秘密にする）。
平文 $m=7$ を暗号化すると、$c=m^e$ を $n$ で割った余り $=7^3=343=6\times55+13$ より $c=13$。
復号は、$c^d=13^{27}$ を 55 で割った余りを計算すると、確かに 7 に戻る（Python の pow(13, 27, 55) で確かめられる）。
$e$ と $n$ を知っていても、$d$ を求めるには $n$ を $p\times q$ に分解する必要がある。実際の RSA 暗号では $n$ が 600 けた程度の数なので、現在のコンピュータでは現実的な時間で分解できない。
・公開鍵暗号で「送信者の公開鍵で暗号化する」と誤る。それでは送信者の秘密鍵でしか復号できず、受信者が読めない。
・デジタル署名で暗号化と同じ鍵の使い方をしてしまう。署名は送信者の秘密鍵で作る。
・パリティで「誤りを必ず検出できる」と考える。偶数個のビットの誤りは検出できない。
・パスワードの組合せ数を $L^k$（長さの種類乗）と逆にする。正しくは $k^L$。
(1) 可用性（壊れたり消えたりしても復元して使い続けられる）　(2) いえない。どちらも知識情報で、異なる種類の要素を組み合わせていないから。　(3) $\frac{10\times9}{2}=45$ 個　(4) 1 が4個なので、奇数にするため 1 を追加して 10110101
・データの尺度：名義尺度（区別だけ）・順序尺度（順序に意味）・間隔尺度（差に意味）・比例尺度（比にも意味）。前の2つが質的データ、後の2つが量的データ
・関係データベースはデータを表で管理する。行＝レコード、列＝フィールド。各行を一意に識別する列（の組）が主キー
・関係演算：選択（条件に合う行を取り出す）・射影（列を取り出す）・結合（共通の列で表をつなぐ）
・オープンデータ＝誰でも二次利用できるルールで、機械判読に適した形式で、無償で公開されたデータ
・分析の前に、欠損値・外れ値・表記ゆれ・単位の不統一などを処理する（前処理）

講義2　データベースと主キー

データベースは、大量のデータを、検索・追加・更新しやすいように整理して蓄積したものである。データベースを管理するソフトウェア（DBMS）は、①データに矛盾が生じないようにする（一貫性の維持）、②複数の利用者が同時に更新しても正しく処理する（同時実行制御。同じ座席を二重に予約させない）、③障害が起きても元の状態に回復できるようにする、④利用者ごとにアクセス権を設定する、といった役割をもつ。
関係データベース（リレーショナルデータベース）は、データを表（テーブル）で管理する。表の1行が1件のデータ（レコード）、各列が項目（フィールド、属性）である。
各レコードを一意に識別するための列を主キーという。主キーの値は、①重複しない、②空（未入力）にならない、ことが必要である。1つの列で決まらないときは、複数の列の組合せを主キーにする（複合キー）。ほかの表の主キーを参照する列を外部キーといい、表どうしを関連づけるのに使う。
なお、大量で多様なデータを高速に扱うため、表の形にこだわらない NoSQL（キーと値の組で管理するものなど）も使われている。
ある高校の生徒の表は、「生徒番号・氏名・クラス・出席番号・住所」の列からなる。生徒番号は入学時に全員に異なる番号がつけられ、出席番号はクラスごとに 1 から振られている。

解　(1) 生徒番号　(2) 同姓同名の生徒がいる可能性があり、値が重複しうるから。　(3) クラスと出席番号の組合せ（同じクラスに同じ出席番号はなく、クラスが違えば同じ出席番号でも区別できる）。

講義1　代表値と散らばり

データの中心を表す値を代表値という。平均値 $\bar x$（合計÷個数）、中央値（小さい順に並べたときの中央の値。個数が偶数なら中央の2つの平均）、最頻値（最も多く現れる値）がある。平均値は極端な値（外れ値）に引っぱられやすいので、所得のように一部に極端に大きな値があるデータでは中央値も見る。
データの散らばりは、範囲（最大値－最小値）のほか、各値と平均値の差（偏差）を使って表す。偏差の合計は必ず 0 になるので、偏差を2乗して平均した分散 $s^2$ を使い、その正の平方根を標準偏差 $s$ という。標準偏差はデータと同じ単位をもち、大きいほど散らばりが大きい。表計算ソフトでは、平均値は AVERAGE、中央値は MEDIAN、分散は VAR.P、標準偏差は STDEV.P などの関数で求められる。
10 人の小テスト（10 点満点）の得点が 3, 5, 6, 6, 7, 8, 8, 8, 9, 10 であった。(1) 平均値・中央値・最頻値を求めよ。(2) 分散と標準偏差を求めよ（標準偏差は小数第2位を四捨五入）。(3) 10 点の人の得点が誤って 30 点と入力されていたとすると、平均値と中央値はどうなるか。
解　(1) 平均値 $70\div10=$ 7 点。中央値は5番目と6番目の平均 $(7+8)\div2=$ 7.5 点。最頻値は 8 点（3人）。
(2) 偏差は $-4,-2,-1,-1,0,1,1,1,2,3$。2乗の和は $16+4+1+1+0+1+1+1+4+9=38$。分散 $38\div10=$ 3.8、標準偏差 $\sqrt{3.8}\fallingdotseq$ 1.9 点。
(3) 合計が 20 増えて平均値は 9 点になるが、中央値は 7.5 点のまま（並び順の中央は変わらない）。

講義2　四分位数と箱ひげ図

データを小さい順に並べ、中央値で前半と後半に分ける（個数が奇数のときは中央値を除く）。前半の中央値を第1四分位数 $Q_1$、全体の中央値を第2四分位数 $Q_2$、後半の中央値を第3四分位数 $Q_3$ という。$Q_3-Q_1$ を四分位範囲といい、中央付近の約半数のデータの散らばりを表す。最小値・$Q_1$・$Q_2$・$Q_3$・最大値の5つ（五数要約）を図にしたものが箱ひげ図で、箱の中に約半数のデータが入る。平均値を ＋ で書きこむこともある。
$Q_1-1.5\times(Q_3-Q_1)$ より小さい値や、$Q_3+1.5\times(Q_3-Q_1)$ より大きい値を外れ値とみなし、ひげの外に点で示す方法もある。
箱ひげ図は、複数の集団の分布を並べて比べるのに向いている。ただし、分布の細かな形（山が2つあるかなど）はわからないので、必要に応じてヒストグラムも見る。

講義3　散布図・相関係数・回帰直線

2つの量の関係は散布図で見る。右上がりの傾向を正の相関、右下がりを負の相関、どちらでもないものを相関がないという。
強さは相関係数 $r=\dfrac{s_{xy}}{s_xs_y}$ で表す。$s_{xy}=\dfrac1n\sum(x_i-\bar x)(y_i-\bar y)$ を共分散という。$r$ は $-1$ 以上 $1$ 以下で、$1$ に近いほど強い正の相関、$-1$ に近いほど強い負の相関、$0$ に近いほど直線的な関係が弱い。
データの傾向を表す直線 $y=ax+b$ を回帰直線といい、$a=\dfrac{s_{xy}}{s_x^2}$、$b=\bar y-a\bar x$ で求める（各点と直線との縦方向のずれの2乗の和が最小になる直線）。回帰直線は必ず平均の点 $(\bar x,\bar y)$ を通り、$x$ から $y$ を予測するのに使える。
ただし、相関は因果関係を意味しない。「アイスクリームの売上」と「水難事故の件数」には正の相関があるが、どちらも「気温」という第3の要因に左右されているだけである（疑似相関）。また、データの範囲の外まで回帰直線で予測すると、大きく外れることがある。

講義4　クロス集計

質的データどうしの関係は、2つの項目の組合せごとに人数を数えたクロス集計表で調べる。人数のままでは集団の大きさが違うと比べにくいので、行（または列）ごとの割合に直して比べる。どちらの合計を 100 % にするかは、何と何を比べたいかで決める。

講義5　仮説検定の考え方 ― 偶然かどうかを確率で判断する

あるコインを 20 回投げたら表が 15 回出た。このコインは「表が出やすい」といえるだろうか。

①主張したいこと（表が出やすい）と反対の仮説「表と裏の出やすさは同じ（表の確率 $\frac12$）」を立てる。
②この仮説が正しいとして、表が 15 回以上出る確率を求める。表が 15〜20 回となる出方は ${}_{20}\mathrm{C}_{15}+\cdots+{}_{20}\mathrm{C}_{20}=15504+4845+1140+190+20+1=21700$ 通りなので、確率は $21700\div2^{20}=21700\div1048576\fallingdotseq0.021$。
③あらかじめ決めた基準（有意水準。5 % がよく使われる）より小さいので、「仮説のもとではめったに起こらないことが起きた」と考えて仮説を棄却し、「表が出やすい」と判断する。
表が 14 回なら、14 回以上の確率は約 0.058（5 % より大）で仮説は棄却できず、「表が出やすいとはいえない」となる（出やすさが同じだと証明されたわけではない）。
